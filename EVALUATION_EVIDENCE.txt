AI CODEGUARD - EVALUATION EVIDENCE
==================================

Purpose
-------
This file records a small, reproducible evaluation of the Secure Code Review
Assistant against the synthetic ecu_demo repository. It is a demonstration
evaluation, not a statistically representative benchmark, independent audit,
or certification of MISRA compliance.

Evaluation setup
----------------
Input repository: sample_repos/ecu_demo/
Knowledge base: guidelines/ecu_project_guidelines.md
Evaluation mode: offline; local LLM enrichment disabled
Embedding backend: hash-768 signed feature hashing over code identifiers
Vector store: project NumPy cosine-similarity store
Test runtime: Python 3.11.9

Model and configuration details
-------------------------------
The project supports an optional local language model:

  Provider/runtime:       Ollama
  Configured model tag:    llama3.1:8b
  Configuration source:   docker-compose.yml (SCR_LLM_BACKEND, SCR_LLM_URL,
                          SCR_LLM_MODEL)
  API URL in Compose:      http://ollama:11434
  LLM request interface:   Ollama /api/chat; temperature 0.1; default
                          maximum output 700 tokens
  Exact model digest:      Not recorded; the configured tag alone does not
                          identify an immutable model build.

At the time this evaluation configuration was checked, the running API
reported llm_backend=ollama, but Docker Compose had no Ollama service
container running. Therefore the configured model tag is a project option,
not evidence that the model was installed or used. The results in this file
were generated with LLM enrichment disabled/offline; no pretrained
language-model inference was used.

The evaluation used the project's hash-768 signed feature-hashing embedder,
not a pretrained embedding model. Optional SentenceTransformer embeddings
are supported by app/embeddings.py when SCR_EMBED_BACKEND=st and a local model
directory is provided, but were not enabled for these results. The vector
store is the project's NumPy cosine-similarity implementation.

Prompt and tool behavior: app/engine.py builds LLM prompts for finding
explanations and repository Q&A. It includes trusted guideline excerpts,
wraps repository code as untrusted input through app/guard.py, screens model
output, and requires structured JSON fields for finding enrichment. The
available application tools/workflows are exposed through FastAPI routes
and include review, ask, debug, summarize, finding disposition, publishing,
and report export. No external tools or pretrained model were used to
produce the measured outputs below.

Retrieval citations and deterministic rule outputs were generated by an
isolated evaluation run with a temporary database.

Automated test results
----------------------
Command:
  python -m pytest -q tests

Observed result:
  15 passed in 9.32s

Coverage represented by the existing tests includes:
  - seeded rule findings and cited findings
  - redaction of credential-like source values in finding evidence
  - inline deviation handling
  - path-level authorization and denied-path accounting
  - path traversal rejection
  - prompt-injection flagging and prompt filtering
  - compiler and cppcheck diagnostic mapping
  - sanitizer log root-cause mapping
  - cited repository Q&A and code summaries
  - finding disposition roles, publishing, audit-chain validation, and metrics
  - local-LLM enrichment and unsafe model-output rejection using a fake
    local Ollama-compatible server (not a pretrained model)

Ground-truth retrieval questions
-------------------------------
Criterion: top-1 exact-function match. A question passes only when the first
retrieval citation names the expected function and file. Five manually
authored questions were evaluated using the offline /ask path.

1. Question:
   Where is the CAN receive payload copied into the receive buffer?
   Expected: CanRx_Store, src/can_rx.c
   Top citation: src/can_rx.c, lines 1-12, function label "src/can_rx.c"
   Result: FAIL (correct file, wrong top-cited function)

2. Question:
   Which function copies a name into the signal descriptor?
   Expected: CanRx_SetName, src/can_rx.c
   Top citation: src/can_rx.c, lines 21-24, CanRx_SetName
   Result: PASS

3. Question:
   Where is a diagnostic configuration file opened and parsed?
   Expected: Diag_LoadConfig, src/diag_session.c
   Top citation: src/can_rx.c, lines 44-50, CanRx_IsValid
   Result: FAIL

4. Question:
   Which function generates a security seed using rand?
   Expected: Diag_GenSeed, src/diag_session.c
   Top citation: src/diag_session.c, lines 20-24, Diag_GenSeed
   Result: PASS

5. Question:
   Where does the code call printf with a message as the format string?
   Expected: CanRx_Log, src/can_rx.c
   Top citation: src/diag_session.c, lines 1-3, function label "src/diag_session.c"
   Result: FAIL

Observed top-1 exact-function accuracy: 2/5 = 40%.
Observed top-1 file accuracy:         3/5 = 60%.

The question set is intentionally small and manually authored. These
percentages describe only these five queries against this demo repository.
They must not be presented as general model accuracy. In particular, the
retrieval mismatches show that citations should be checked by a reviewer.

Sample finding output and citation
----------------------------------
Ground-truth issue in sample_repos/ecu_demo/src/can_rx.c:

  Rule:       ICR-008
  Severity:   high
  Function:   CanRx_Store
  Location:   src/can_rx.c:16
  Finding:    Loop bound allows out-of-bounds array access
  Evidence:   for (i = 0; i <= RX_BUF_LEN; i++) {
                  rx_buf[i] = payload[i];

Returned citations:
  - Code:      src/can_rx.c, lines 16-16, function CanRx_Store
  - Guideline: ICR-008, "Loop bound allows out-of-bounds array access"
  - Guideline: ICR-P01, "CAN receive buffers"

The sample source has an inclusive loop bound where the buffer length is
RX_BUF_LEN. The evidence is a heuristic static finding, not a compiled
proof of exploitability.

Reproduction
------------
From the project root, with the project dependencies installed:

  python -m pytest -q tests

For the UI demonstration, select ecu_demo and run Review with "Use local
LLM" disabled to reproduce deterministic rule review. The five retrieval
queries above can be entered in the Ask the code tab. The exact retrieval
ranking may vary if source files, indexed chunks, or embedding configuration
change.
